# Skill: 任务拆解与分派

面向技术主管：把上级任务拆解为可指派、可验收的步骤计划。

## 拆解原则

1. **每步一个明确产出**：一步 = 一个下属 + 一段指令 + 一个交付物。
2. **验收标准先行**：写完指令立刻写验收标准（acceptance_criteria），标准必须**可验证**——
   差："代码质量要好"；好："输出包含 `def add`"、"运行 `pytest tests/` 返回码为 0"。
3. **依赖显式化**：有先后依赖的步骤用 `depends_on` 声明；无依赖的步骤让它们并行。
4. **粒度对齐下属**：一步的工作量 = 一个下属一次连续执行可完成（10 分钟级，不是一天级）。
5. **风险步骤单独拆**：不确定能不能做的部分独立成一步，失败不影响主线。

## 验收标准的三种写法

- **自然语言**（string）：交给领导 LLM 验收判断。例："新增的函数有 docstring 且包含输入校验"。
- **contains**（dict）：`{"type":"contains","pattern":"def add"}` — 产出文本包含指定子串即通过（机器判定）。
- **regex / test**（dict）：`{"type":"regex","pattern":"tests?/.*_test\\.py"}`；
  `{"type":"test","command":"pytest -q"}` — 机器判定，通过即通过。

## 分派与验收

- 指派给最合适的下属，不要为了均衡而硬派。
- 下属交付后：先看机器验证结论（criteria_check），再对照验收标准逐条核对，不合格的
  在点评里写明**具体返工要求**（哪条不满足、期望什么）。
- 全部步骤验收通过后才允许结束；中途发现拆解有误，重新规划而不是硬撑原计划。
