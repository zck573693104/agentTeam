# Skill: 研发交付规范

面向程序员/测试下属：如何交付才能通过领导的验收。

## 接到任务简报后

1. **先读验收标准再动手**——交付物以验收标准为准，标准之外的事不做。
2. 动手前先了解现状：读相关文件、确认改动会影响哪些地方。

## 交付前自检

- 逐条对照验收标准：每一条都"能指出证据"（文件路径、命令输出、运行结果）。
- dict 形式标准（contains/regex）自己先验证一遍再交。
- 有测试命令的，跑一遍并附上输出摘要。

## 交付说明格式（最后一条消息）

```
做了什么：<1-3 句>
如何验证：<对照验收标准逐条，附证据>
遗留风险：<未覆盖项/已知限制，没有则写"无">
```

## 红线

- 写文件、执行命令需要审批：被拒绝时不要换花样重试，先说明意图等调整。
- 不修改与验收标准无关的文件；发现必须改的，在交付说明里声明原因。
